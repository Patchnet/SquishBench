# SquishBench one-shot prompt

Copy everything between the rulers verbatim.

Do not edit this file to suit a particular model. If the contract genuinely needs to change,

---

Build a browser-based fidget toy: a squishy object floating between two disembodied hands that
the user can grab, stretch, squash, twist, and toss.

## Deliverable

A static site that runs by opening `index.html` in a modern browser.

- Vanilla HTML, CSS, and JavaScript only. No build step, no framework, no bundler.
- No network requests at runtime — no CDN scripts, no web fonts, no image URLs. Everything
  must work offline from the local files.
- Split the work across at least three files: `index.html`, `styles.css`, and `main.js`.
  More files are fine if they earn their place.
- Draw the objects and hands with CSS, inline SVG, or canvas. No binary image assets.

## The stage

A single centered play area holding three things:

1. **A left hand**, anchored at a fixed spot on the left side of the stage. It does not chase
   the pointer. It is the fixed grip.
2. **A right hand**, which follows the pointer continuously whenever the pointer is over the
   stage.
3. **The squishy object**, floating between them.

The hands are disembodied — just hands, no arms, no body.

## Idle behavior

When nothing is being held, the object drifts in a slow, gentle float near the center of the
stage, with a small breathing deformation. It should read as alive, not as a static image.

## Interaction model

**Grab.** Pressing the primary pointer button on the object grabs it. The object is now held
between the anchored left hand and the pointer-driven right hand.

**Pull → stretch.** While grabbed, moving the pointer away from the left hand stretches the
object along the axis between the two hands. It gets longer on that axis and thinner across it.

**Push → squash.** Moving the pointer toward the left hand squashes the object: shorter along
the grip axis, fatter across it.

**Side motion → twist.** Moving the pointer perpendicular to the grip axis shears the object.
Twist composes with stretch and squash — a pull that also moves sideways reads as both.

**Rotation.** The object's long axis tracks the line between the two hands, so the whole thing
rotates as the pointer swings around the anchored left hand.

**Release.** Releasing the pointer button lets the object spring back with a short overshoot
wobble that settles to rest — not a linear snap.

**Toss.** Right-clicking the stage tosses the object through an arc to the other hand. The
browser context menu must not appear. Tosses alternate: the first goes to one hand, the next
comes back. The object spins in flight and lands settled in the receiving hand.

Deformation must be bounded. No matter how far the pointer travels, the object never inverts,
never collapses to zero, and never leaves the stage.

## Object picker

Three selectable objects, switchable at any time without reloading:

- **Ball** — a plain squishy stress ball
- **Cow** — recognizably a cow (ears, horns, spots, eyes, muzzle)
- **Pizza** — recognizably a pizza slice (crust, sauce, cheese, toppings)

All three obey the same physics. Switching objects keeps the toy running and gives some visible
acknowledgement.

## Feedback

A visible status readout naming the current object and what is happening to it right now —
floating, gripped, stretched, squished, twisted, released, airborne, caught. It updates live
during interaction.

An on-screen hint tells a first-time visitor how to play, without them having to guess that
right-click does anything.

## Input and accessibility

- Mouse and touch both work. On touch, the toy is still grabbable and stretchable, and there is
  a reachable way to trigger the toss that does not require a right mouse button.
- Selecting an object works by keyboard.
- The picker controls are real buttons with accessible names and pressed state.
- The status readout is announced to assistive tech when it changes.
- Honor `prefers-reduced-motion: reduce`: keep the toy fully usable, but drop the idle drift and
  the flight/wobble animations to something still or near-instant.
- Text stays legible in both light and dark color schemes.

## Quality bar

- No uncaught console errors, and none logged during normal play.
- No stuck states: if the pointer leaves the stage, the window loses focus, or a touch is
  cancelled mid-grab, the object releases cleanly instead of staying frozen mid-stretch.
- The page stays responsive on a small viewport (roughly 360px wide) and on a wide one.
- Animation runs off the compositor where practical — prefer transforms over layout-triggering
  properties in the per-frame path.

Judgement calls not covered above are yours. Make the thing feel good.
